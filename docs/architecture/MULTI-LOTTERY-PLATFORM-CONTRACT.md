# 多彩种平台隔离契约

## 核心原则

现阶段不抽走或重写大乐透生产核心。平台先建立共享的产品入口和目录规范，各彩种在独立边界内实现；待两个以上彩种稳定运行后，再把确实相同的代码提升为公共组件。

## 数据分层

| 层 | 内容 | 是否客户可见 |
|---|---|---|
| 官方事实 | 期号、赛程、停售、开奖结果、奖金公告 | 是 |
| 分析事实 | 公开指数、程序换算、组合与成本 | 是，必须说明含义 |
| AI 记录 | 证据约束下的综合解释与复盘 | 只展示客户文案 |
| 运行元数据 | 模型、提示词、时间、哈希、重试、文件路径 | 否 |

## 隔离要求

- 大乐透继续只读写现有 `data/dlt_*`、`public/data/*.json` 和 D1 表。
- 足彩只读写 `data/football/` 与 `public/data/football/`。
- 两个 GitHub Actions 使用不同文件、任务名和 concurrency group。
- 足彩任务不调用 `src.scheduler`、`src.publisher` 或任何大乐透推荐写入脚本。
- 足彩失败不得提交空文件、删除旧文件或触发大乐透重新生成。

## 统一能力接口

每个彩种最终都应提供：`validate_input`、`identity_hash`、`build_plan`、`settle`、`build_ai_evidence`、`publish`。当前足彩模块已实现前四项，AI证据与发布位于独立闭环脚本中；后续验证第二个彩种后再正式抽象接口，避免为了抽象而破坏稳定代码。
