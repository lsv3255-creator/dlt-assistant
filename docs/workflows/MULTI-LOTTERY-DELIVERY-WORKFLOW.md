# 多彩种分析网站交付工作流

## 目标

把已经在大乐透验证过的“权威数据 → 程序计算 → 在线 AI 解释 → 冻结发布 → 开奖复盘 → 自动更新”闭环，复制到新的彩种，同时保证任何新彩种故障都不影响已上线彩种。

## 每个彩种必须完成的九个步骤

1. **玩法定义**：记录官方规则、号码或赛果空间、投注单位、停售和开奖时间。
2. **数据契约**：区分官方事实源、分析数据源和 AI 输出；每个字段标明来源与更新时间。
3. **身份冻结**：以彩种、期号、停售时间和完整场次/号码身份生成 SHA-256；发布后不得改写。
4. **确定性计算**：由程序完成概率换算、组合数量、成本、命中和奖级计算；AI 不负责算数。
5. **AI 综合分析**：在线免费模型只解释已给证据、比较取舍和风险；不得补造新闻、走势、伤停或中奖承诺。
6. **双重校验**：结构校验、数据身份校验、输出文案校验均通过才发布；失败保留上次已核验结果。
7. **赛后复盘**：只对开奖前冻结方案复盘，不允许赛后补推荐；未取得正式结果时保持待复盘。
8. **隔离自动化**：每个彩种使用独立 workflow、并发组、数据目录和公开文件；失败不可级联。
9. **上线验收**：本地测试 → PR/合并 → 自动任务 → Cloudflare 部署 → 手机端正式域名检查 → 任务文档归档。

## 不可跨越的发布门禁

- 官方期号或完整玩法身份缺失：不生成推荐。
- 场次调整未复核：停止发布新方案。
- 分析数据不完整：显示“数据待更新”，不让 AI 猜测。
- 在线 AI 失败：程序结果可保留，但明确显示 AI 更新中，不冒充 AI 已完成。
- 已过停售时间且没有事前冻结记录：不得补写当期推荐。
- 正式赛果未核验：不得声称命中或中奖。
- 新模块测试失败：不修改、不阻断大乐透生产流水线。

## 统一目录约定

```text
data/<lottery>/                 后台原始资料、冻结归档
src/<lottery>/                  玩法规则、计算与结算
scripts/<lottery>_cycle.py      单彩种闭环入口
public/<lottery>.html           客户页面
public/data/<lottery>/          客户可读发布数据
.github/workflows/<lottery>.yml 独立自动任务
tests/test_<lottery>_module.py  契约与回归测试
```

## 客户页面边界

页面只展示期号、比赛/号码、公开依据、AI 分析、方案、成本、风险提示和赛后复盘。模型名称、密钥、内部版本、生成时间、哈希、文件路径、缓存状态、重试过程和后台错误均不得呈现给客户。

|---|---|---|---|
